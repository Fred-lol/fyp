# Learned strategy ranking

The default shared generate_plan function calls a trained multi-output ridge regressor. It predicts the relative quality rank of each geometric packing strategy from load and lorry features. Predicted ranks determine search order under the existing time budget; geometric feasibility checks and independent validation determine acceptance. Orientations are still selected by the geometric search, not by a learned placement model.

Training: run `.venv/Scripts/python scripts/train_strategy_model.py` from the repository root. NumPy 2.5.4 is pinned. Seeds 0-79 train the model; seeds 80-99 are held-out scenarios. Labels come from actual independently validated packing results, ranked by the optimizer objective. Synthetic scenarios are small (4-18 boxes) and are not production fleet evidence.

The checked-in JSON artifact contains only coefficients and metadata, never executable pickle data. Missing, incompatible or malformed artifacts fall back to the fixed strategy order. Training does not run at application startup. Historical plans are untouched.

Evaluation is recorded in ml_evaluation.json. On held-out scenarios both modes found 17/20 valid layouts, with equal compactness on all 17. Three scenarios yielded no validated complete layout in either mode. Mean successful-run times were approximately 0.097 seconds each. These results do not demonstrate improved final packing quality; full search often visits all strategies. The learned first-choice mean relative rank was 0.154 versus 0.242 for the fixed first strategy. Larger and production-like workloads need further evaluation.

No optimality or zero-gap guarantee is made. Deployment and live inference must be verified separately; repository push and an HTTP health response do not establish the deployed commit.

## Projected-face search update

The candidate generator now projects faces from different boxes onto the floor and includes opposite-face alignment. The final score includes measured between-box floor-row gaps, and lateral bounding width is translation-invariant. Previous search candidates remain available for comparison. The model was retrained for the revised search (held-out first-choice rank 0.150 versus 0.175 fixed-first). See gap_evaluation.json for before/after coordinates, scores, methods, timing and exact floor-row gap areas on synthetic scenarios. These are not measurements of the user's unavailable Supabase plan. Restraint review remains necessary even when the measured row-gap area is zero; this is not a dynamics/safety certification.


## Validated physical refinement

The default Generate/Regenerate shared engine now performs a bounded second pass after ML-ranked geometric search. It jointly rotates/repositions floor-box pairs and then evaluates individual face-aligned relocations and permitted horizontal 90-degree rotations. It never tips insulated boxes onto their sides. Each accepted change passes the complete independent validator, including support, stack load, dimensions, identity/count and loading sequence. Gaps, occupied depth, stack count and deepest-wall anchoring cannot worsen. Balance-only score changes are not counted as geometry improvements. The previous validated candidate remains the fallback when time expires or no improvement is found. The refinement has a maximum two-second allocation inside the existing overall search budget.

`python scripts/evaluate_refinement.py` records complete before/after coordinates and scores in refinement_evaluation.json. Across 20 held-out synthetic scenarios, both versions produced 17 valid complete plans; eight improved and none worsened. Internal floor-row gaps totaled 8,400 -> 4,150 cm2; occupied depth totaled 3,545 -> 3,525 cm; stacked boxes remained five. Mean successful runtime was 0.35 -> 0.83 seconds in this run (machine/load dependent). Three cases remained unsolved, not certified impossible. These measurements exclude outer unused width and do not prove optimality or eliminate the need for cargo restraints.

A separate read-only replay of latest Supabase Plan #9 (290 x 160 x 160 cm, 1,000 kg capacity; six boxes, 300 kg) executed ML inference. Before and after remained at zero internal floor-row gap, 288 cm occupied depth and zero stacks. Refinement correctly retained the unchanged layout; no improvement is claimed for this plan. The user's intended screenshot was unavailable. Production replay details are retained locally in artifacts/latest_plan_refinement.json; historical Supabase records were not modified.


## Cavity-first search (v4)

The former score minimized raised volume and a floor rectangle before considering y-axis floor gaps. It could report zero gaps while longitudinal or upper-layer cavities remained. The new coordinate-compressed measurement sweeps all vertical slabs and measures the union of empty cells bounded by cargo along either horizontal axis, plus empty cells below cargo. Outer spare lorry space and open space above shorter boxes are excluded. This explicitly defined measure is not a proof that every possible diagonal/open cavity is absent or that cargo needs no restraints.

All new Generate and Regenerate calls go through `preview_optimization -> generate_plan`. Candidate selection now prioritizes measured internal cavity volume, then floor preference, side-face contact, occupied footprint and depth. Bounded beam repacking explores alternative box orders, permitted footprint rotations and positions jointly. Pair/single refinement follows. Complete candidates and final results pass the independent validator; the best available validated candidate remains the fallback. Insulated-box height stays upright; only horizontal 90-degree rotations are permitted by the existing profiles. No global optimum is claimed.

The existing NumPy ridge strategy ranker was retrained against the new objective: 80 training scenarios and 20 separate test scenarios. Mean held-out first-choice relative rank is 0.3175 versus 0.3675 fixed-first (lower is better). The model ranks initial searches; the actual improvements reported here come from the complete hybrid geometric search, not proof of an isolated ML effect.

`python scripts/evaluate_cavity_search.py` replays the previous checked-in scenarios and coordinates. Results in `cavity_evaluation.json`: 17/20 valid complete plans before and after; 15 cases have lower internal-gap volume and none higher. Total measured gaps 555,125 -> 151,875 cm3; occupied depth 3,525 -> 3,055 cm; side contact 287,450 -> 291,700 cm2. Stack count increases from 5 to 26 because cavity reduction outranks floor preference; every stack passes full support and cumulative load checks. Three cases remain unsolved, not proven impossible. Average successful runtime approximately 0.83 -> 3.07 seconds in these runs; timings depend on CPU contention and the bounded search can select different valid fallbacks on larger loads.
